# CTF 资产-能力-路径 方法论

## 核心原则
不要先问“能打什么”，先问“最后要什么能力”。

## 三层拆解
### 1. 资产
可被持有、可被利用的对象：
- token
- cookie
- session
- workspace
- 邮箱
- 代理
- 账号

### 2. 能力
资产最终要转化成的可计分能力：
- 保活
- 续期
- 成功请求
- 入池
- 稳定演示

### 3. 路径
把资产转成能力的实际路线：
- producer
- consumer
- proxy
- fallback
- sidecar

## 操作顺序
1. 先定义最终能力。
2. 再定义最小必需资产。
3. 最后再决定去哪拿这些资产。

## 调试原则
- 用 A/B 测试确认错误是在资产层、路径层还是适配层。
- 优先做最短闭环。
- 当源头太难打时，优先改中间层或消费端去适配已有资源。
- 成功后必须补日志、usage、状态机、演示恢复材料。
